CEL Run Pipeline

How one run moves from a config to the paper's tables, where the API calls happen, and how each call is counted when methods are compared at a matched budget.

The run: one step spends, everything after it replays

Every step is python experiments/scripts/<step>.py -c configs/smoke.yaml. Only collect.py reaches a model; every later step reads what it cached.

What collection spends on one question

Collection records a superset: everything any method could ask for. The paraphrases and every flip (probe) are real calls, split across three model roles.

How one case is counted when methods are compared

At evaluation, each method replays the recorded calls it would have made and counts them. CEL pays for its paraphrases and its flips; baselines are then given CEL's mean spend per case (the matched budget).

The smoke run's budget

TriviaQA × gpt-4.1, 60 questions (10 dev + 50 eval, one batch of 50), no re-drawn batches. From estimate.py -c configs/smoke.yaml --reseed-batches 0.
